## gui/batch_mode_widget.py (7)

  - *Fix:* Import apply_splitter_style from gui/common/splitter_style.py and call apply_splitter_style(splitter) after line 68.
- 🔴 **[status-console] :167** (BatchModeWidget) — The widget performs long-running provider operations (create_batch_job submission at line 345, job polling at line 406, result download at line 452) but has no DialogStatusConsole from gui/llm_utils.py — only a single-line QLabel (self.status_label) that truncates errors to 50 chars (line 369) and overwrites each message. AGENTS.md §8 requires a status console at the bottom, separated by a splitter, showing real-time progress for LLM/long operations.
  - *Fix:* Add a DialogStatusConsole at the bottom of the layout inside a vertical QSplitter (styled with apply_splitter_style), and log submission details, per-job poll results, and full error text to it instead of the truncated QLabel.
- 🔴 **[usability] :345** (BatchModeWidget._submit_batch) — batch_manager.create_batch_job() is called synchronously on the GUI thread. The indeterminate progress bar enabled at lines 340-341 never animates because the event loop is blocked, and the whole window freezes during network submission. Same pattern in _poll_job_status (line 406, fired by a QTimer every 30s — periodic UI freezes) and _download_results (line 452, blocking download of all image bytes). Project convention is async generation via QThread workers.
  - *Fix:* Move create_batch_job, get_job_status polling, and get_job_results into a QThread/QThreadPool worker emitting progress signals; only update UI (progress bar, status console) from the main thread.
- 🟡 **[splitter] :134** (BatchModeWidget) — The queue/jobs splitter has setChildrenCollapsible left at the default True and no QSettings persistence — either the prompt queue or the jobs list can be dragged to zero width and disappear (compounded by the invisible default handle), and the 500/500 split resets every session.

- 🟡 **[hotkey] :174** (BatchModeWidget) — Neither audited file defines a single keyboard shortcut. The primary action "Submit Batch Job" has no Ctrl+Enter binding (project convention: Ctrl+Enter = primary action), and the prompt queue list has no Delete-key binding for "Remove Selected" — everything is mouse-only.
  - *Fix:* Add QShortcut(QKeySequence("Ctrl+Return"), self, self._submit_batch) and a QShortcut(QKeySequence.Delete) scoped to queue_list (Qt.WidgetWithChildrenShortcut) wired to _remove_selected.
- ⚪ **[usability] :76** (BatchModeWidget.queue_list) — queue_list uses the default SingleSelection mode, so the "Remove Selected" button (whose plumbing at lines 260-265 already iterates multiple selectedItems correctly) can only ever remove one prompt at a time — removing 20 of 50 imported prompts takes 20 click cycles.
  - *Fix:* self.queue_list.setSelectionMode(QAbstractItemView.ExtendedSelection) — and pop queued_prompts indices in descending-row order to stay aligned when multiple rows are removed.
- ⚪ **[accessibility] :145** (BatchModeWidget) — No label buddies or mnemonics anywhere: the "Batch Size:" QLabel has no setBuddy(self.batch_size_spin) and no & accelerator, and none of the 8 buttons in either file has a mnemonic. Combined with the total absence of shortcuts, keyboard users have to Tab through everything. The Refresh Status, Download Results, and Submit Batch Job buttons also lack tooltips while their siblings (import/export, batch size, cost) have them.
  - *Fix:* Create the label as QLabel("Batch &Size:") with setBuddy(batch_size_spin), add mnemonics to frequently used buttons (e.g. "&Submit Batch Job", "&Remove Selected"), and add tooltips to refresh_btn, download_btn, and submit_btn.
